# 의류 MD 사례 데이터 설계 (2026-10-28)

> **화면 종료 (2026-10-28):** 이 합성 사례의 화면과 API는 제거했다. 판매까지 지어낸 자료로는 실제 수요를 추정할 수 없기 때문이다. 지금은 H&M 실제 판매에 회사 내부 자료(재고 수불·원가·시즌 상태·작년 비교)를 대신할 가상 운영 조건을 결합한 사례를 쓴다. 이 문서는 그 내부 자료를 어떻게 설계할지 보여주는 참고 자료로만 남긴다.

## 출처와 범위

모든 상품·판매·재고 수불·작년 비교 상품은 **포트폴리오용 합성 데이터**다. 회사의 실제 판매·재고·이익 또는 실제 할인 효과가 아니다. 공공자료는 이 사례의 입력이나 포트폴리오 근거로 사용하지 않는다.

| 파일 | 단위 | 행 수 | 역할 |
|---|---|---:|---|
| `fashion_products_realistic_v2.csv` | SKU, 8월 31일 | 30 | 상품, 현재고, 입고 예정, 현재 판매가·원가 |
| `fashion_daily_sales_realistic_v2.csv` | SKU×일자 | 1,800 | 7월 3일~8월 31일 판매·매출·매출총이익; 과거 판매가 변동 반영 |
| `fashion_merchandising_context.csv` | SKU | 30 | 시즌, 출시일, 재발주 가능 여부 |
| `fashion_stock_flow_2026.csv` | SKU×일자 | 1,800 | 일별 기초·입고·반품·조정·판매·마감 재고 |
| `fashion_prior_fw_reference.csv` | 2026FW SKU에 연결된 *별도* 2025FW 비교 상품 | 12 | 작년 판매율과 다음 시즌 물량 검토의 비교 기준 |

`generate_operations.py`는 원본 상품·판매 CSV를 읽어 뒤의 두 파일을 재현한다. 새 파일은 기존 상품·판매 값을 바꾸지 않고 별도 DB 테이블에 한 번만 추가된다. 이미 있는 운영 자료는 덮어쓰지 않는다.

## 재고 수불 검증

일별 마감재고 = 기초재고 + 기간 입고 + 재판매 가능 고객 반품 − 공급사 반품 − 폐기 + 재고 조정 − 판매. 다음 날 기초재고는 전날 마감재고와 같아야 한다. 운영 파일의 판매 수량은 원본 일별 판매 파일과 일치하고, 마지막 날 마감재고는 원본 상품 마스터의 8월 31일 현재고와 일치해야 한다. `inbound_units`는 **미래 입고 예정**이므로 과거 재고 수불에 포함하지 않는다.

현재 합성 수불은 60일 30개 상품 총 기초재고 3,067개 + 기간 입고 134개 − 판매 864개 = 마감재고 2,337개다. 고객 반품·공급사 반품·폐기·조정은 이 버전에서 0이다. 따라서 해당 예외의 처리 구조는 있으나 복잡한 예외를 검증한 자료로 소개하지 않는다.

## 지표와 가정

- **기간 판매율** = 기간 판매 수량 / (첫날 기초재고 + 기간 입고 + 재판매 가능한 고객 반품 − 공급사 반품 − 폐기 + 재고 조정). 분모가 0이면 계산하지 않는다. 출시 전 신상의 0%는 수요 평가에 사용하지 않는다.
- 작년 F/W 자료는 **동일 SKU의 실적이 아니다.** 각 신상품에 대응시킨 가상의 비교 상품이다. 이름과 연결 관계를 화면에 명시한다.
- **올해 예상 수요** = 올림(작년 비교 상품 판매량 × (1 + 사용자가 입력한 성장률)). 이것은 실측 예측이 아닌 시나리오 가정이다.
- **목표 준비 물량** = 올림(올해 예상 수요 / 목표 판매율). **추가 발주 검토량** = max(목표 준비 물량 − 현재고 − 입고 예정, 0). 현재 준비 물량이 목표보다 많으면 초과 물량과, 그중 아직 입고되지 않아 조정 검토가 가능한 최대 물량을 별도 표시한다. 이미 보유한 재고를 발주 취소 가능한 물량으로 표시하지 않는다. 30일 내 입고 가능성, 최소 발주 단위, 공급사 조건은 아직 반영하지 않는다.
- 예상 매출·매출총이익은 현재 상품 판매가·원가와 시나리오 판매량으로 계산한다. 수수료·배송비·광고비·반품 비용이 없어 순이익은 계산하지 않는다.
- 다음 시즌 기획 판단은 상품, 성장률, 목표 판매율, 서버가 재계산한 당시 물량 검토값, MD가 쓴 이유를 별도 DB에 저장한다. 이 기록은 실제 발주나 재고를 변경하지 않는다.

## 현재 구현의 경계

상품 입력이나 판매를 수정하면 원본 합성 수불표가 자동으로 소급 수정되지는 않는다. API는 현재 DB와 수불표의 일치 여부를 SKU별로 표시한다. 불일치 상품의 수불 판매율을 현재 실적으로 해석하면 안 된다. 현재 수불 파일에는 입고일은 있지만 **발주일·발주 리드타임의 실측 이력, 옵션/사이즈, 실제 행사별 가격 변동, 반품 사유**는 없다. 다음 단계에서는 이 자료를 별도 테이블과 입력 화면으로 추가해 공급 지연, 옵션 품절, 행사 전후 성과를 분석한다.
