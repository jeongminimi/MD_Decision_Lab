# MD Decision Lab — 사례 연구

> **[직접 작성]** 표시는 기획자 본인이 채워야 하는 부분이다. 실무 경험의 구체적인 수치·상황은 본인만 확인할 수 있으므로 지어내지 않는다.

## 한 줄 소개

주니어 MD가 **8월 31일 시점에 알 수 있던 정보만으로** 상품별 재고 위험을 판단하고, 그 판단을 9월 실제 판매로 돌아보는 도구. 판매는 H&M 실제 거래 기록, 재고·발주·원가는 공개 자료로 구할 수 없는 회사 내부 자료를 대신한 가상 운영 조건이다.

## 1. 출발점: 현장에서 겪은 문제

기획자는 의류 매장 총괄과 신규 온라인 브랜드 MD 업무를 약 2년간 맡았다. 시즌 전 인기 상품 수량을 예상해 확보하고, 주간 판매율을 보며 본사와 재고·위탁·반품을 조율했다. 매입·출고·재고는 월별 엑셀로 주고받았고, 목표 매출에 맞춰 프로모션과 VIP 판매를 운영했다.

**[직접 작성]** 실제로 겪은 판단 사례 1개 — 예: 어느 시즌, 어떤 상품을, 어떤 숫자를 보고, 무엇을 결정했고, 결과가 어땠는지. 그 판단에서 아쉬웠던 정보가 무엇이었는지.

여기서 세 가지 문제를 정의했다.

1. 판매가 빠른데 다음 입고 전에 재고가 먼저 떨어지는 상품을 늦게 알아챈다.
2. 판매가 꺾였는데 재고가 쌓이는 상품의 할인 시점을 놓친다.
3. 내가 내린 판단이 맞았는지 나중에 돌아볼 기록이 없다.

## 2. 데이터 설계: 실제 판매 + 생성한 내부 자료

MD 판단에는 판매·재고·발주·원가가 함께 필요하다. 공개 자료(H&M Kaggle)에는 판매만 있다. 그래서 데이터를 네 층으로 나눴다.

| 층 | 내용 | 출처 |
|---|---|---|
| 수요 | 일별 판매, 작년 같은 기간 판매 | **H&M 실제 거래 기록** |
| 내부 운영 조건 | 재고 수불, 발주·리드타임, 판매가·원가, 시즌 상태 | **생성** (회사 내부 자료 대신) |
| 판단 | 소진 위험·재고 과다·판매 변화, 조치안 비교 | 계산 |
| 검증 | 9/1~9/22 판매 | **H&M 실제 거래 기록** |

판단 기준일을 2020-08-31로 고정하고, 표본 선정부터 재고 설정까지 그 이후 판매는 쓰지 않았다. 9월 판매를 지우고 다시 생성해도 8/31까지의 결과가 같다는 점을 검사로 확인한다.

## 3. 8월 31일의 판단

H&M 여성복 3개 섹션의 7~8월 판매 상위 286종 중 46종에 가상 운영 조건을 붙였다.

| 판정 | 상품 수 | 판정 기준 |
|---|---:|---|
| 재고 0 | 1 | 기준일 재고 없음 |
| 소진 위험 | 13 | 재고 소진 예상일 ≤ 입고 리드타임 |
| 재고 과다 | 20 | 재고 소진 예상일 ≥ 60일 |
| 판매 감소 / 증가 | 2 / 4 | 최근 14일이 직전 14일보다 30% 이상 감소 / 증가 |
| 정상 | 6 | 위 조건 없음 |

조치안 비교는 예상 판매를 날짜별로 나눠, **입고 전에 재고가 비는 날이 있으면 30일 합계가 충분해도 불가로 판정**한다. 처음 구현에서는 합계만 비교했고, 기준일 재고와 30일 안의 계획 입고를 모두 판다고 가정하면, 계획 입고가 있는 상품 19종 중 10종이 입고 전 공백을 숨긴 채 "가능"으로 나왔다.

## 4. 9월에 돌아본 결과

**판정 유형별 회고** (8/31 직전 14일 → 이후 22일 일평균 판매, 실제 기록)

| 8/31 판정 | 일평균 변화 | 가상 정책상 공급 부족 | 가상 재고 8/31 → 9/22 |
|---|---:|---|---:|
| 소진 위험 13종 | −35% | 10종 · 4,248개 | 417 → 8,283개 |
| 재고 과다 20종 | −43% | 0종 | 9,454 → 8,783개 |
| 판매 증가 4종 | −36% | 0종 | 1,557 → 1,697개 |

- 재고 과다 판정 상품은 22일 뒤에도 재고의 93%가 남았다. 할인 검토가 필요했던 이유를 보여준다.
- 공급 부족은 모두 8/31에 소진 위험·재고 0으로 표시된 상품에서만 생겼다.
- **모든 판정 유형에서 9월 판매 속도가 떨어졌다.** "판매 증가"로 본 상품도 마찬가지였다. 7~8월 판매 상위 상품은 9월에 꺾이는 경향이 있었다.

**9월 판매 추정** (8/31까지의 실제 판매만 사용, 판매가 있던 H&M 220종 전체로 비교)

| 방식 | 합계 차이 | 상품별 오차율 |
|---|---:|---:|
| 최근 14일 속도 유지 | +35.5% | 53.1% |
| 작년 계절 보정 (× 0.735, 2019년 같은 기간 변화) | −0.4% | 43.0% |

작년 계절 변화를 상품마다 따로 적용하면 오히려 오차가 커졌고(75.5%), 표본 전체 비율로 적용했을 때 합계가 맞았다. 시험하고 버린 방식과 그 사실을 2020년 결과를 본 뒤 알았다는 점은 `docs/WORKSPACE_DATA.md`에 공개했다.

## 5. 이 숫자로 말할 수 없는 것

- 재고·발주·원가가 가상이므로 **H&M의 실제 품절이나 잃은 매출이 아니다.** 공급 부족분은 8/31 이후 새 발주를 넣지 않은 가상 규칙의 영향도 받는다.
- 판정이 "맞았다"는 적중률을 계산하지 않는다. 회고 표는 판정 뒤에 관측된 흐름을 나란히 놓은 것이다.
- 추정의 합계가 맞아도 상품별 오차는 43%로 크다. 표본은 여름 판매 상위 상품이라 H&M 전체를 대표하지 않는다.
- 조치 전후 비교는 대조군이 없어 인과 효과를 증명하지 않는다.

## 6. 보완점: 생성한 자료를 실제 자료로 바꾸면

| 생성한 자료 | 실제 회사 자료로 바꾸면 | 연결 통로 |
|---|---|---|
| 8/31 재고, 일별 재고 수불 | 실측 판매율, 실제 품절일 확인 | 자사 업로드의 `stock_on_hand`, `opening_stock`, `received_units` |
| 발주일·입고 예정일·리드타임 | 공급사별 실제 지연을 반영한 재고 공백 판단 | `inbound_units`, `inbound_date`, `lead_time_days` |
| 판매가·원가 (상품 종류별 등급표) | 실제 매출총이익과 할인안 비교 | `unit_price_krw`, `unit_cost_krw`, 판매 파일의 `revenue`, `gross_margin` |
| 시즌 상태 (여름 잔여·가을 신상·겨울 이월) | 상품 상태별 판단 질문 적용 | `lifecycle` |
| 반품·재고 조정 | 수불 불일치 원인 확인 | 아직 없음 (다음 단계) |

사이즈·컬러별 재고, 구매 예산(OTB), 채널별 프로모션 효과는 자료가 없어 이번 범위에서 제외했다. 판매 기록이 없는 신상은 이 규칙으로 판단할 수 없으므로, 초도 물량은 별도 기준이 필요하다.

## 7. 역할 구분

- **기획자**: 문제 정의, 판단 기준(소진 위험 = 리드타임 대비 재고, 재발주 불가 상품은 추가 매입 제외 등), 데이터 층 구분, 결과 검수와 화면 문구 수정. **[직접 작성]** 본인이 특히 결정하거나 고친 부분 2~3개.
- **AI 코딩 도구**(Codex, Claude Code): 구현, 테스트 작성, 데이터 검증 스크립트. AI가 만든 결과도 테스트·브라우저 확인을 거친 범위만 설명한다.
