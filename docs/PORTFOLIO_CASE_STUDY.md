# MD Decision Lab — 포트폴리오 사례 초안

## 30초 소개

상품별 판매와 재고를 함께 보며 MD가 **무엇을 먼저 확인하고, 왜 확인해야 하며, 다음에 어떤 조치를 검토할지** 결정하도록 돕는 도구입니다. 판매 기록을 집계하고 재고를 입력하면 품절·과잉재고·수요 변화 위험을 표시하며, 각 판단에 사용한 숫자와 규칙을 확인할 수 있습니다. 추천은 검토용이며 발주·할인·콘텐츠 게시를 자동 실행하지 않습니다.

## 출발점: 현장에서 겪은 문제

프로젝트 기획자는 의류 매장 총괄과 신규 온라인 브랜드 MD 업무를 약 2년간 맡았습니다. 시즌 전 인기 상품 수량을 예상해 확보하고, 주간 판매율을 보며 본사와 재고·위탁·반품을 조율했습니다. 매입·출고·재고를 월별 엑셀로 주고받고, 목표 매출에 맞춰 프로모션과 VIP 판매 활동도 운영했습니다.

이 과정에서 **판매가 빠른데 재고가 부족한 상품**, **판매가 둔화됐는데 재고가 쌓이는 상품**, **조치 후 무엇이 달라졌는지 확인하기 어려운 상황**을 한 화면에서 판단할 수 있으면 좋겠다는 문제를 정의했습니다. 위 경험은 문제 선택의 근거입니다. 현재 프로그램이 실제 매장의 매출을 높였다는 증거는 아닙니다.

## 사용 흐름

1. 상품·판매 CSV를 불러오거나, Olist의 과거 판매 기록을 연결합니다.
2. 재고·입고 예정·리드타임·목표 보유일·원가를 입력합니다. Olist에는 실제 재고가 없으므로 이 값은 **별도 가정**으로 저장합니다.
3. 상품별 판매 속도와 재고 커버 일수를 계산해 위험을 분류합니다. 최근 7일 판매가 30일 흐름과 크게 다르면 표본 규모와 경고를 함께 확인합니다.
4. 추가 매입, 프로모션, 라이브 노출, 관찰 같은 **검토할 행동**을 제안하고 근거를 표시합니다.
5. MD가 검토한 행동을 기록합니다. 전후 자료가 충분할 때만 기술적 비교를 보여주며, 조치가 변화를 일으켰다고 단정하지 않습니다.

## 실제 화면에서 검증한 사례

- Olist의 배송 완료 주문 **96,211건**, 상품 항목 **109,880건**, 상품 **32,081개**를 과거 판매 자료로 연결했습니다. 브라질 헤알(BRL) 기준이며 배송비는 상품 매출에서 제외했습니다.
- 상품 5개의 재고를 가정한 두 시나리오를 비교했습니다. 같은 과거 판매에 다른 재고를 적용했을 때 품절·품절 위험 상품은 **1개 → 0개**, 가정 재고 가치는 **R$14,280 → R$15,500**으로 표시됩니다. 이는 **가정 변경에 따른 계산 결과**이며 매출 개선 실적이 아닙니다.
- 30일에 58개 팔렸지만 최근 7일 판매가 0개인 상품은 재고가 적어 보여도 즉시 매입 수량을 추천하지 않습니다. 먼저 행사 종료, 품절, 노출 중단 또는 데이터 누락을 확인하도록 안내합니다.
- 브라우저에서 첫 화면, Olist 상품 카드, 숫자 근거 이동, 재고 시나리오 전환을 확인했습니다.

## 구현 범위

- **데이터 저장:** SQLite에 상품·판매·재고 시나리오·조치 기록·숏폼 초안을 분리해 저장합니다.
- **분석:** FastAPI 백엔드에서 판매 속도, 재고 커버, 위험 신호와 추천 근거를 계산합니다. 화면은 백엔드의 결과와 출처를 보여줍니다.
- **화면:** React에서 우선 검토 상품을 먼저 제시하고, 필요한 경우 상세 수치와 규칙을 열어볼 수 있게 했습니다.
- **콘텐츠:** 숏폼은 상품 요약을 명시적으로 받아 초안을 만드는 별도 흐름입니다. 영상 생성이나 자동 게시 기능은 없습니다.

## 기획자의 기여와 AI 활용

기획자는 MD 현장 경험을 바탕으로 문제·입력 항목·판단 기준·사용 흐름을 정하고, 결과물의 문구와 화면을 검토·수정했습니다. 구현 과정에는 Codex 등 AI 코딩 도구를 사용했습니다. 코드를 혼자 작성했다고 주장하지 않으며, AI가 만든 기능도 실제 데이터와 브라우저에서 검증한 범위만 설명합니다.

## 한계와 다음 검증

- Olist에는 실제 재고와 원가가 없어 두 값은 사용자가 입력한 시뮬레이션입니다.
- 과거 판매가 향후 수요를 보장하지 않습니다. 계절성, 행사, 가격, 채널 변화는 별도 검토가 필요합니다.
- 조치 전후 비교는 상관된 변화만 보여줍니다. 비교군이 없는 상태에서 매출 상승의 원인을 특정할 수 없습니다.
- 현재 검증은 로컬 프로토타입과 합성·공개 자료에 한정됩니다. 실제 업무 도입 전에는 사용자 CSV 형식, 데이터 품질, 권한, 예외 사례를 더 확인해야 합니다.

## 포트폴리오에 넣을 화면

1. 첫 화면: 우선 확인 상품·이유·다음 조치
2. Olist 화면: 실제 판매와 가정 재고의 출처 구분
3. 상품 근거: 7일·30일 판매와 위험 분류의 판단 이유
4. 두 재고 가정 비교: 같은 판매에 다른 재고를 적용했을 때의 차이

> 화면 캡처는 최신 브라우저 화면으로 다시 준비합니다. 현재 문서의 숫자는 앱에서 확인한 로컬 시나리오의 예시이며 사용자 기업의 성과 수치가 아닙니다.
