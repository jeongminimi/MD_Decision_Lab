# MD Decision Lab 사용 방법

개발을 배우지 않아도 **상품을 고르고, 판매 전략을 계산하고, 판단을 저장하는 흐름**을 따라 할 수 있습니다. 처음에는 저장소에 포함된 가상 의류 자료만 사용하세요. H&M 파일은 필요하지 않습니다.

## 이미 화면이 열려 있다면

백엔드와 화면 서버가 켜져 있을 때 [프로그램 열기](http://localhost:5173/)로 이동하고 아래 **첫 사용: 가상 의류 자료 연결**부터 시작하세요. 화면에 “작업공간 연결”만 보인다면 자료를 연결해야 합니다. 화면이 열리지 않으면 아래 설치·실행 순서를 따르세요.

## 처음 설치하기 (Windows)

1. [Python](https://www.python.org/downloads/) **3.11 이상**과 [Node.js](https://nodejs.org/) **20 이상**을 설치합니다. Python 설치 화면에서 **Add python.exe to PATH**를 선택하세요.
2. [프로젝트 GitHub](https://github.com/jeongminimi/MD_Decision_Lab)에서 초록색 **Code → Download ZIP**을 누릅니다. 압축을 풀고 `MD_Decision_Lab-main` 폴더를 `C:\`로 옮깁니다. 최종 위치가 `C:\MD_Decision_Lab-main\README.md`인지 확인하세요.
3. 시작 메뉴에서 **PowerShell**을 엽니다. 아래 명령을 한 줄씩 붙여넣고 Enter를 누릅니다. 설치는 처음 한 번만 하면 됩니다.

```powershell
cd C:\MD_Decision_Lab-main\backend
python -m pip install -r requirements.txt
cd ..\frontend
npm.cmd install
```

## 프로그램 켜기

PowerShell 창을 **두 개** 열어 각각 실행하고, 사용하는 동안 두 창을 열어 둡니다.

첫 번째 창 — 분석 기능:

```powershell
cd C:\MD_Decision_Lab-main\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`Application startup complete`가 보이면 준비된 것입니다.

두 번째 창 — 화면:

```powershell
cd C:\MD_Decision_Lab-main\frontend
npm.cmd run dev
```

`Local: http://localhost:5173/`가 보이면 브라우저에서 [http://localhost:5173/](http://localhost:5173/)을 엽니다. 주소의 숫자가 다르게 표시되면 두 번째 창에 나온 주소를 사용하세요.

## 첫 사용: 가상 의류 자료 연결

1. `오늘의 할 일` 화면에서 **상품·판매 파일 연결**을 엽니다.
2. 작업공간 이름에 `가상 의류 공개 데모`, 재고 기준일에 **2026-08-31**을 입력합니다.
3. **상품 파일**에 `C:\MD_Decision_Lab-main\sample_data\public_demo\products.csv`, **일별 판매 파일**에 같은 폴더의 `sales.csv`를 선택합니다.
4. **선택 기간의 모든 판매가 포함돼 있습니다**와 **가상 데이터로 표시**를 모두 선택하고 **파일 검증 후 연결**을 누릅니다.

상품 30종과 판매 기록이 표시되면 연결에 성공한 것입니다. 이 자료의 판매·재고·가격은 모두 **가상**입니다. 연결할 때마다 새 작업공간이 생기므로 이미 연결했다면 상단의 **작업공간** 목록에서 기존 것을 선택하세요.

## 상품 판단하기

1. **오늘의 할 일**에서 가장 먼저 확인할 상품과 그 이유를 봅니다. 상품을 선택하거나 **전체 상품**에서 다른 상품을 엽니다.
2. 최근 판매량, 재고 소진 예상일, 판매율, 현재 재고와 가격을 확인합니다. 판매율이 `계산 안 함`이면 기초재고·기간 입고가 없거나 재고 수불이 맞지 않는 상태입니다.
3. 재고·판매가·원가를 바꾸려면 상품의 **현재 재고·판매가·원가 입력**을 열고 값을 수정한 뒤 **입력값 저장**을 누릅니다. 공개 데모에서는 수정값도 시험용 가정입니다.
4. 아래 **판매 및 마케팅 전략**에서 `가격 할인`, `온라인 기획전`, `상품 노출`, `라이브 노출`, `추가 매입` 중 하나를 고릅니다. 재발주 불가 상품은 추가 매입을 선택할 수 없습니다.
5. **현재 운영 유지 시 예상 판매량**과 **선택한 전략의 예상 판매량**을 각각 입력합니다. 화면의 최근 30일 판매량은 참고치이며, 전략으로 판매가 얼마나 늘지 자동으로 예측하지 않습니다. 할인 전략이라면 할인율도 입력합니다.
6. **예상 이익·재고 계산**을 누르고 두 결과의 **매출총이익**, **남는 재고**, **재고 공백**을 비교합니다. 이익이 가장 큰 쪽이 반드시 정답은 아닙니다. 조치 비용과 브랜드 운영 목적도 판단에 포함하세요.
7. 선택할 결과 카드를 누르고 **이 판단을 선택한 이유**를 다섯 글자 이상 적어 **판단 저장**을 누릅니다. 재고 공백 때문에 가정한 판매량을 공급할 수 없는 결과는 저장할 수 없습니다.
8. **내 결정 기록**에서 저장한 이유와 당시 수치를 확인합니다. 저장은 실제 할인·발주·기획전 실행을 뜻하지 않습니다.

### 숫자를 읽는 법

| 화면의 말 | 의미 |
|---|---|
| 최근 30일 판매 | 선택한 기준일 이전에 기록된 판매 수량 |
| 재고 소진 예상일 | 최근 판매 속도가 계속된다고 가정할 때 재고가 버틸 기간 |
| 판매율 | 기간 판매량 ÷ (기초재고 + 기간 입고). 재고 수불이 맞을 때만 표시 |
| 예상 매출총이익 | 예상 판매량 × (할인 후 판매가 − 상품 매입원가) |
| 재고 공백 | 예상 판매가 입고보다 빨라 재고가 부족해지는 첫날과 부족 수량 |

기획전·진열·라이브의 성과는 **직접 입력한 예상 판매량**에만 반영됩니다. 방문자·노출 수가 없으므로 전환율은 계산하지 않습니다. 매출총이익에는 광고비, 라이브 제작비, 배송비, 수수료, 반품비가 포함되지 않습니다. 결과는 실제 매출 상승이나 순이익이 아닙니다.

## 자사 파일을 연결할 때

첫 사용과 같은 **상품·판매 파일 연결**에서 CSV 또는 XLSX 두 파일을 고릅니다. 형식은 [상품 예시](../sample_data/company_products_template.csv)와 [판매 예시](../sample_data/company_sales_template.csv)를 참고하세요. 상품에는 `sku`, `name`, 판매에는 `sku`, `sale_date`, `units_sold`가 필요합니다. 재고·원가처럼 선택 입력값이 없으면 해당 계산을 할 수 없습니다. 판매가 빠진 날을 0개 판매로 봐도 되는 경우에만 **선택 기간의 모든 판매가 포함**을 선택하세요. 자사 자료에 **가상 데이터로 표시**를 선택하지 마세요.

실제로 조치한 뒤 결과를 보려면 **내 결정 기록**에서 실행일을 기록하고, **조치 후 판매 자료 추가**로 같은 상품의 새 판매 파일을 연결한 다음 **전후 판매 확인**을 누릅니다. 전후 비교는 변화의 기록이며 조치가 원인이라는 증명은 아닙니다.

## H&M 사례는 선택 사항

H&M 거래 원본은 이 저장소에 없습니다. [Kaggle 데이터 페이지](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data)에서 규칙에 동의해 자료를 받은 경우에만 [README의 H&M 준비 절차](../README.md#3-hm-데이터-준비-선택)를 진행하세요. 화면에서 **운영 시뮬레이션 자료 연결**을 누르면 실제 판매 수량과 가상 재고·가격·원가를 함께 볼 수 있습니다. H&M 가격값을 원화 매출로 해석하지 않습니다.

### 동종 상품과 다음 시즌 비교

1. **전체 상품**에서 의류나 액세서리 상품을 검색해 누릅니다. 상세의 **동종 상품과 판매 비교**에서 같은 섹션·종류의 최근 7일·14일 판매 순위와 수량을 봅니다. 판매가 있었던 상품끼리 매긴 순위입니다.
2. 재고 시뮬레이션이 연결된 상품은 **오늘의 할 일**에서 열면 판매 순위와 함께 가상 재고, 소진 예상일, 추가 매입 검토 기준을 볼 수 있습니다. 재고 자료가 없는 액세서리는 판매 비교까지만 표시됩니다.
3. **다음 시즌 기획**에서 의류 또는 액세서리를 고르고, 섹션과 종류를 선택합니다. 2019년과 2020년 7~8월 주간 판매 막대를 비교한 뒤 후보 상품 2~5종을 고릅니다.
4. 후보별 **준비 물량**과 **판단 이유**를 입력해 저장합니다. 저장한 수량은 기획 가정이며 실제 발주가 아닙니다. 두 해의 상품 수나 노출량이 달라질 수 있으므로 판매량 차이를 그대로 수요 증가나 전략 효과로 읽지 마세요.

## 종료하거나 막혔을 때

끝낼 때는 두 PowerShell 창에서 각각 `Ctrl + C`를 누릅니다. 저장한 판단과 작업공간은 로컬 DB에 남습니다.

| 증상 | 먼저 확인할 것 |
|---|---|
| 화면이 열리지 않음 | 두 번째 PowerShell 창의 `Local:` 주소와 실행 상태 |
| 화면은 열리지만 자료가 없음 | 첫 번째 PowerShell 창이 켜져 있는지, 작업공간을 선택했는지 |
| `python`을 찾지 못함 | Python 설치 시 PATH 선택 여부를 확인하고 PowerShell을 다시 열기 |
| PowerShell에서 `npm` 실행 오류 | `npm.cmd` 명령 사용 |
| `No module named app` | 첫 번째 창에서 `backend` 폴더로 이동했는지 확인 |
| 포트가 이미 사용 중 | 같은 프로그램이 다른 창에서 실행 중인지 확인. 해당 창을 사용하거나 종료 후 다시 실행 |
| 계산 버튼이 비활성화 | 같은 기준일의 현재 재고, 입고 예정량, 원화 판매가, 상품 매입원가 입력 여부 확인 |
| 재고 공백이 나옴 | 예상 판매량과 입고 예정일을 확인. 늦게 들어오는 재고는 앞선 판매를 공급할 수 없음 |
